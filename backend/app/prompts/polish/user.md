## 二、歌词润色要求

1. 保留用户明确提供的故事事实、人物关系、时间线和结局。
2. 不得擅自增加具体对话、表白现场、对方回应、异地或重逢等未提供的事件。
3. 不得将 AI 推断的场景意象改写为用户明确提供的事实。
4. 优化生硬、不自然、空洞、刻意煽情的歌词表达。
5. 保留原歌词中自然、有感染力的句子，不要为了修改而修改。
6. 不强制押韵，不强制每句字数一致。
7. 保持歌词的可唱性、情绪连贯性和整体结构。
8. 这是第二轮编辑，不是重新创作。不得随意推翻原有创作方向。
9. 必须输出完整歌词，不能只输出修改过的句子。
10. 重点检查副歌是否具有清晰的核心表达和容易记住的 Hook。
11. 检查歌词的断句、字数、语义重音和句尾表达是否适合演唱。
12. 不要为了追求旋律效果而牺牲歌词原本的语义和情感。

## 三、旋律与演唱设计要求

完成歌词润色后，必须以最终润色后的歌词为基础，制定旋律与演唱指导方案。

### 3.1 整体旋律方向

明确整首歌曲的旋律特征，包括：

- 旋律整体风格和情绪方向。
- 主歌与副歌应该形成怎样的旋律对比。
- 整首歌曲最重要的旋律记忆点。
- 演唱应该采用怎样的情绪表达方式。

### 3.2 分段旋律设计

结合实际歌词结构，分别设计：

**主歌（Verse）**
- 采用什么样的旋律表达方式。
- 如何体现故事叙述感。
- 如何避免机械朗读。
- 如何为副歌积累情绪。

**预副歌（Pre-Chorus）**
- 如何逐步提升旋律和情绪张力。
- 如何自然衔接副歌。
- 如何让听众期待副歌到来。

如果原歌词没有预副歌，不得强行增加。

**副歌（Chorus）**
- 如何形成明显的旋律记忆点。
- 核心 Hook 应如何演唱。
- 如何与主歌形成明显的旋律和情绪对比。
- 哪些关键词适合突出表达。
- 如何避免副歌与主歌听起来过于相似。

**桥段（Bridge）**
- 如何形成情绪或旋律上的变化。
- 如何为最终副歌做准备。
- 不得为了填写设计内容而虚构桥段。

**最终副歌（Final Chorus）**
- 如何在原副歌基础上进一步增强情绪。
- 如何通过演唱力度、和声或声音表现形成高潮。
- 如何保持与原副歌的主题一致。

### 3.3 人声演唱指导

重点解决人声像 AI 朗读、缺乏旋律感和情绪感染力的问题。

根据歌曲实际情况，明确：

- 人声整体演唱方式。
- 主歌和副歌的声音表现差异。
- 咬字、气息和演唱力度。
- 长音、连音、停顿和换气的使用。
- 情绪递进和高潮部分的表达。
- 如何避免整首歌曲采用相同的音量、节奏和情绪。

要求自然、有旋律感、有情绪变化，不能像朗读歌词。

### 3.4 歌词与旋律匹配

必须检查最终歌词与旋律设计之间的匹配关系：

- 歌词自然重音是否适合旋律表达。
- 核心 Hook 是否具有足够的旋律表现空间。
- 长句是否存在演唱困难。
- 句尾是否具有合理的延长音或停顿空间。
- 旋律情绪是否符合歌词实际含义。

如果发现歌词本身不适合演唱，应先调整歌词，再制定旋律方案。

注意：旋律设计是音乐创作指导，不是精确音符、MIDI 或乐谱，不得编造已经确定的音高和音符信息。

## 四、输出格式要求

必须严格按照 System Prompt 定义的完整 JSON Schema 输出。

特别注意：

1. 必须包含全部顶层字段，不能只输出 song。
2. 必须保留原有 JSON Schema 中的字段名称和层级。
3. song 必须包含完整的歌曲信息、标题、创作概念、完整歌词、核心记忆点和创作说明。
4. song.vocal_melody_design 必须完整输出，不能省略旋律与演唱设计。
5. vocal_melody_design 必须根据最终润色后的歌词制定，不能脱离实际歌词进行泛泛描述。
6. 对于歌曲中不存在的段落，对应设计字段填写空字符串，不得擅自增加歌词段落。
7. vocal_techniques 和 breathing_and_phrasing 应填写实际适用的演唱技巧、断句和换气建议。
8. quality_check 必须包含完整的质量检查结果，包括 melody_design。
9. next_step 必须保留，并设置 action 为 GENERATE_MUSIC_PROMPT。
10. 对于没有新增内容的字段，根据原始策划和当前歌词填写，不要随意编造。
11. 不得删除、合并或自行简化任何规定字段。
12. 最终歌词必须与旋律设计保持一致。
13. 只输出合法 JSON，不要输出 Markdown 代码块、解释、前言或总结。

## 五、内部执行顺序

请在内部严格按照以下顺序完成，不要输出分析过程：

1. 理解用户原始需求和歌曲策划。
2. 分析当前歌词的问题。
3. 完成歌词第二轮润色。
4. 检查歌词自然度、韵律、可唱性和副歌记忆点。
5. 确定最终完整歌词。
6. 根据最终歌词设计各段旋律与演唱方式。
7. 检查人声表达、情绪递进和歌词旋律匹配度。
8. 完成质量检查。
9. 输出完整、合法的 JSON。
